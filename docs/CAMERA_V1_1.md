# V1.1 底板 FPC2 摄像头调用

本仓库后续板端测试默认使用自研 V1.1 底板，以 `SCH_载板V1.1_2026-11-13.pdf`
为接线基准。本文适用于底板的 FPC2，已验证 OS04A10 和 MaixPy 4.12.5。

## 接线与故障原因

原理图第 2 页给出如下接线。

| FPC2 信号 | FPC2 引脚 | SoC 接口 | SoC 引脚 |
|---|---:|---|---|
| CAM_SCL | 19 | I2C7_SCL | A8 |
| CAM_SDA | 21 | I2C7_SDA | A9 |
| SENSOR_RSTN0 | 17 | 摄像头复位 | 由原摄像头驱动配置 |
| MCLK0 | 18 | 摄像头时钟 | 由原摄像头驱动配置 |
| 3V3 | 22 | 摄像头模组电源 | 底板 3V3 |

CAM_SCL/SDA 经 Q1 ES3134KZ 做 1.8 V / 3.3 V 电平转换，再经 51 Ω 串联电阻
接 I2C7。A8/A9 的 pad 地址分别为 `0x0230006c` / `0x02300078`，
`[18:16]` 应设为复用值 3。

MaixPy 4.12.5 默认在 `/dev/i2c-0` 探测和配置摄像头。实测在该底板上会报告
I2C0 `lost arbitration`，读取首帧失败。改用 I2C7 后能够读出 OS04A10 芯片 ID
`0x530441`，但多媒体初始化又会把 A8/A9 从 `0x30083` 重置为 `0x83`，导致
后续传感器寄存器访问报 `Remote I/O error`。

适配库拦截独立摄像头进程的 `open/open64/openat/openat64`，将精确路径
`/dev/i2c-0` 转到 `/dev/i2c-7`。每次打开时检查并补回 A8/A9 的 I2C7 复用。
该进程内所有打开 I2C0 的操作都会经过这条重定向，因此本工具用于独立取帧。
系统 `/dev/i2c-*` 节点和启动配置保持原有设置，适配随子进程结束而卸载。

底板舵机 0/1 口使用 A24/A25（I2C0/PWM0/PWM1），FPC2 使用 A8/A9（I2C7）。
物理引脚独立，多媒体初始化与其他外设程序的并发行为仍需单独验证。本工具取得
摄像头、舵机和双 IMU 测试工具的互斥锁，并检查已打开的摄像头/I2C7/SPI 设备。

## 构建和上传

开发机指定 AArch64 编译器后运行。板卡本地构建可使用 `CC=gcc`。

```sh
ARM_CC=/path/to/aarch64-none-linux-gnu-gcc bash tools/build_camera_v11.sh
scp -r build_camera_v11 root@192.168.137.253:/root/camera-v11-20261120
```

板端 root 终端执行，`--out` 每次使用新的目录。

```sh
cd /root/camera-v11-20261120
sha256sum -c SHA256SUMS
python3 run_camera_v11.py --out /tmp/camera-v11-run01
```

一次测试固定使用 `640×480 RGB888 @ 30 fps`，预读 15 帧后检查 90 帧。正常耗时数秒，
25 秒未结束会终止采集子进程。Ctrl+C 也会停止采集，随后恢复 A8/A9 的原始 pad 值。
成功时退出码为 0，`result.json` 的 `status` 为 `PASS`，`pins_restored` 为 `true`。

输出包括 `capture.log`、`capture.json`、`result.json` 和 `frame.png`。结果记录尺寸、
格式、有效帧数、接收帧率、64 点 RGB 网格变化、I2C 错误数、复用修复次数和恢复情况。
网格变化用于辅助检查图像内容更新；静止或全黑场景中网格重复仍可能是有效采集。
帧率使用主机单调时钟统计接收时刻，曝光时序和长期丢帧另行测量。

重新加载库后运行普通 `camera.Camera(640, 480, fps=30)` 即可通过 FPC2 取图。
直接调用时应沿用运行入口的独占检查和退出恢复。升级 MaixPy 或更换传感器后重新验收。
[MaixPy 摄像头 API](https://wiki.sipeed.com/maixpy/api/maix/camera.html)

## 2026-11-20 实机记录

设备为 `maixcam2-e1fa`，地址 `192.168.137.253`，摄像头为 OS04A10，MaixPy 4.12.5。
客户端日期采用 Asia/Shanghai，帧率按板端单调时钟计算。

| 项目 | 原始适配实测结果 |
|---|---|
| 芯片 ID | `0x530441`，I2C7 地址 `0x36` |
| 图像 | 640×480，RGB888，921600 字节/帧 |
| 有效帧 | 90/90，另预读 15 帧 |
| 接收帧率 | 30.28 fps |
| 网格不同的帧 | 90 |
| I2C 读写错误 | 0 |
| 系统调用核对 | 实际打开 `/dev/i2c-7` |
| 退出恢复 | A8/A9 原值恢复，摄像头设备已释放 |
| 样图 | 已检查，可见桌面场景 |

整理后的运行入口在同一板卡复测通过，90/90 帧有效，约 30.28 fps，I2C 读写错误为 0，
进程内重定向 6 次、补回复用 2 次，退出后 A8/A9 恢复。结构化结果及库/脚本校验值见
[打包后实机验证记录](camera_v1_1_verified_2026-11-20.json)。

原始本地记录位于 `reports/camera_fpc2_2026-11-20/`，板端原始目录为
`/tmp/maixcam2_fpc2_20261120_iefjsvgs`。原始数据、样图和编译产物按仓库忽略规则保存，
本文和 `tools/` 中的源码提供后续复测所需的记录。
